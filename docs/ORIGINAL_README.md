# Liquid Light Studio 2.0

Studio 2.0 keeps the original WebGL renderer, project format and account-owned R2 session storage. The new shell adds a left tool rail; independent expandable, keyboard-reorderable panels; persistent panel layout; a searchable starting-point gallery; and session thumbnail browsing/search. The legacy interface remains available at `/studio.html?classic=1`.

There are 43 starting points (20 new in 2.0). The gallery uses one isolated, low-resolution renderer to lazily produce real artwork previews without touching the main flow. Keep-source and keep-colour choices use the same settings merge for application and preview. Without WebGL, settings and sessions can still be opened and backed up, with an explicit unavailable-preview message; this does not claim rendering or exports work.

Validation: `node --test tests/*.test.mjs`. Existing 90 tests plus setup roundtrip, preservation, and panel-order checks. Browser UI checks cover panel navigation, search, committed field number edits, undo/redo, zoom below 100%, detaching/docking, and reordering. Browser rendering must be reported separately from shader compilation; this environment may not expose WebGL.


A buildless WebGL 2 tool for making liquid light flow from SVG contours.

Import an SVG or use a built-in shape. Adjust source size, position and rotation; flow speed and direction; turbulence, eddy size, evolution, swirl, viscosity, momentum, colour diffusion and trail lifetime. Source Size runs from 15% to 460% of the canvas's shorter side (four times the previous 115% maximum), allowing the artwork to bleed beyond the frame in both the preview and exports. Tune the emission band, glow, reach, falloff, exposure, contour brightness and shape fill.

The gradient editor supports up to eight editable colour stops with linear, radial or angular mapping. Gradient edits recolour existing trails immediately. Background colour and opacity are independent, with a checkerboard behind transparent areas. The cleaner `PS_Blue.svg` supplied by the user is the default source.

Save and open project JSON files containing the SVG and settings. Render PNG frames with solid, partial or fully transparent backgrounds at up to 3840 pixels on the longer side. Export captures directly into an RGBA8 framebuffer, reads and vertically flips its pixels, and encodes them through a separate 2D canvas. The live preview is not resized or used as a transient download buffer. Save PNG invokes a native file picker synchronously from the click when available and writes/closes the original Blob; cancellation, policy blocks and write failures have distinct feedback. A prepared data-URL download bypasses Blob-URL download handling, and a ZIP backup contains the exact same PNG, including alpha. Open image remains available. No download is automatically triggered after asynchronous encoding. Browser-local storage remembers the current project when available.

Animation export starts from the current flow and defaults to 1920-pixel Full HD and High compression quality. With a supported WebCodecs AVC encoder, MP4s render frame by frame at exact timestamps, with bounded encoder queues and no real-time capture deadlines. High/Main/Baseline profiles and quantizer/variable-bitrate modes are probed; Preview/High/Maximum use AVC quantizers 25/18/12 when available, or resolution/frame-rate-scaled bitrates otherwise. The MP4 container preserves decode order, signed presentation offsets, keyframes and encoder colour metadata. If AVC WebCodecs is unavailable, the browser recorder remains a compatibility fallback with higher bitrate targets and a detail content hint; the completed export identifies which method was used. Video backgrounds are solid. Encoded output is capped at 256 MB.

PNG sequences render at exact selected frame intervals, support alpha, and include all numbered frames plus project/timing metadata in one ZIP. Controls cover 1–30 second duration, 24/30/60 fps and sizes through 4K; PNG sequences are limited to 120 frames above 1920 pixels or 480 frames at lower sizes to bound browser memory use. Exports support cancellation and provide a direct Save link only after file generation finishes. Native browser encoding/permission errors are shown in the dialog.

Each slider, dropdown, background colour and gradient stop has a reset. Section resets restore a group of controls; Reset session restores all controls and restarts the flow while retaining the source asset. Restart flow clears only the simulated current.

Serve `dist/` over HTTP. No build or dependency installation is required. The browser must support WebGL 2 and `EXT_color_buffer_float`. Render quality offers 256, 384, 512 (default), 768 and 1024-pixel fluid grids. Higher settings restart the flow and retain finer trails for export. Image exports retain the current flow and render it at the selected size.

The inspector divider supports dragging, arrow keys, Home/End and double-click to reset. Expand preview gives the artwork the full window; Escape restores the inspector. Both export dialogs support corner resizing and an Expand button. PNGs open in Fit mode; 100% uses a scrollable view at the image's native CSS-pixel size. Window sizing does not change export dimensions. Reset session also restores view sizing.

Both previews support close inspection up to 6400%. Live zoom uses a GPU view transform at fixed output resolution, with wheel-to-cursor zoom, numeric zoom, Fit, Pan, Alt-drag and middle-drag. Stirring maps back into the source coordinates correctly. The PNG viewer has its own magnification menu, wheel zoom and drag panning. These view controls leave PNG/video framing and dimensions unchanged.

The app-owned dark Looks menu includes ten PlayStation looks sampled from the supplied core/expanded colour references, plus the five original Studio looks. Core looks pair the two reference blues with white, black or mist. Seven accent looks reserve the first 80% of their angular palette for blue and confine cyan, lime, mint, magenta, coral, violet or the mixed spectrum to the remaining 20%. Their matching endpoints close the colour loop. Existing angular gradients with unequal endpoints blend across a small wrap region, and angular colour drift rotates the palette before wrapping to avoid a hard diagonal seam. The 80/20 balance refers to gradient range; geometry, lighting and flow affect its final pixel area.

Motion → Collide with source is enabled by default and can be toggled without rebuilding the source. The SVG acts as a solid obstacle; its holes remain fluid space. SDF-guided backtracing limits tunnelling through thin parts, boundary velocities remove inward flow, and pressure/diffusion use solid-neighbour conditions. Bloom sampling checks the path to each tap, and the visible halo/rim is clipped outside the source. Shape fill remains a separate intentional interior treatment. Projects remember the toggle and section/session resets restore it.

05 / Effects adds an optional Venetian ribs treatment, disabled by default. Amount, slat count, angle, refraction depth, softness, motion and offset control light-only prismatic ribbing. It reuses the current palette and leaves the source geometry fixed; refraction also respects source collisions. Each effect control and the whole section can be reset.

Update validation: GPU tests checked angular continuity with positive, negative and zero colour drift, zoom correspondence away from resolution-dependent contour antialiasing, and visible Venetian ribs. A thin-wall fixture blocked both dye backtracing and bloom with collision enabled, and allowed both with it disabled; solid interiors stayed empty. Camera math checked cursor anchoring, pan bounds and the 64× limit. All fifteen looks and seven 80/20 accent palettes validated. Effects/collision resets and project validation preserved unrelated settings. Browser UI gestures and the custom popup remain unverified in a browser because the browser QA capability was unavailable.

The solver advects a velocity field, adds curl-noise and vorticity forces, smooths velocities for viscosity, and projects pressure to reduce divergence. A separate contour-driven carrier controls outward, upward, orbital or directional travel. Light density and source coordinates are advected together, enabling live gradient recolouring. Diffusion and exponential decay shape the trails, and multiscale bloom provides the halo.

Light and bloom buffers use 32-bit float precision with explicit bilinear filtering in the solver and positive cubic B-spline reconstruction in the display pass. Contours use 2048-pixel distance fields, or 3072 at High/Maximum quality (limited by the graphics device). SVGs are painted directly into the transformed source canvas instead of rescaling a cropped raster. Screen-space derivative antialiasing keeps the contour transition near one output pixel; midpoint advection and smoothed contour normals reduce stepped flow artifacts. Bloom spread is independent of the fluid grid size, and subtle output dithering reduces 8-bit gradient banding.

Validation: all shader passes compiled and linked in OpenGL ES 3.2; offscreen fluid states remained finite; pressure projection reduced measured divergence; opaque, transparent and 3840 × 2160 rendering passed. Distance fields were checked against a brute-force reference including holes. Export logic checks verified pixel orientation, retained preview size, native PNG encoding, sequence frame counts/timing, ZIP CRC integrity, alpha, cancellation and recorder-error cleanup. Save fixtures verified immediate picker invocation, exact bytes, cancellation and blocked-picker handling. FFprobe and FFmpeg decoded MP4s made by the actual container writer, including all 24 reordered B-frames with identical decoded pixels in the correct presentation order. Encoder contract checks verified exact frame count, duration, quantizer options, queue draining and resource cleanup. Reset checks verified that the imported SVG and unrelated controls are retained. Browser automation was unavailable, so the browser's native WebCodecs/MediaRecorder implementations and actual save/download dialogs were not exercised.
